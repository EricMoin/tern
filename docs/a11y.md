# Accessibility semantics (a11y)

The M4.1 semantics layer: every interactive widget exposes accessibility
metadata — an ARIA `role`, an accessible `label`, active boolean `state`
flags, and the `enabled` / `selected` booleans — through a **parallel
bookkeeping store** that never changes painted cell output. This document
covers the JS API, the native dump shape, the default-off contract, and what
is explicitly **not** shipped yet.

## Scope: the read API only — terminal emission is M4.2

**Terminal a11y emission is NOT shipped in this slice.** Producing an
accessibility stream a screen reader can consume (e.g. iTerm2's a11y report
sequences, or an equivalent generic semantics stream) is M4.2 (P1) and stays
out of scope. What ships is the semantics **tree + read API**: the metadata
is derived per component, stored in a parallel map, and readable through
`Renderer.semantics()` for tests, debugging, and third-party a11y bridges.
No ESC sequence is ever produced.

## The default-off contract

The semantics store is **off by default**:

- A renderer constructed **without** the `semantics` option has a disabled
  native store. `Node.setSemantics` writes are **rejected** natively (and the
  JS wiring — being best-effort — catches the rejection and drops the write,
  never an error), so `Renderer.semantics()` stays empty even after
  `setSemantics` calls.
- A renderer constructed with `semantics: true` opts in: writes land in the
  store and the dump surfaces them.
- `Renderer.setSemanticsEnabled(enabled)` is the **JS-side mirror only** —
  the native store is fixed at construction (there is no native runtime
  toggle). It updates the JS bookkeeping a consumer or a11y bridge can query,
  and it stays in sync with the `semantics` constructor option. Disabling it
  never clears the store: entries written while enabled stay readable (the
  native read is not gated by the flag).

Because the store is pure bookkeeping — a parallel map of node metadata the
compositor never reads — wiring semantics never changes painted cell output.
The cell-output invariance is tested at every layer: natively (the Rust
`semantics_writes_never_change_painted_snapshot_rows` test) and from JS
(`semantics_test.ts`'s `render_to_buffer` golden).

## Roles

The ARIA role vocabulary (`SemanticsRole`):

| Role | Used by |
|------|---------|
| `checkbox` | a `Checkbox` |
| `switch` | a `Toggle` |
| `radiogroup` | a `Radio` root |
| `radio` | one option row of a `Radio` |
| `listbox` | a `Select` |
| `textbox` | an `Input` / `Textarea` |
| `menu` | a `Menu` |
| `button`, `menuitem`, `link`, `group` | reserved for future components (accepted by the native store) |

An unknown role string is rejected natively (the write errors instead of
silently dropping), so a typo surfaces rather than producing wrong metadata.

## State flags

The boolean semantics states (`SemanticsState`) a node's `state` array may
carry:

| Flag | Meaning |
|------|---------|
| `checked` | the control is in its on/selected state (a checked checkbox, an on toggle, the selected radio row) |
| `focused` | the control (or a row within it) is focused |
| `expanded` | a dropdown / menu is open |
| `collapsed` | reserved (a collapsed branch) |

State flags are sorted in the dump for a stable read. An unknown flag string
is rejected natively, like an unknown role.

## JS usage

### Opt in

```ts
import { createRenderer } from "@tern-tui/core";

// The store is off by default; `semantics: true` opts in.
const renderer = createRenderer({ headless: true, semantics: true });
```

### Read the dump

```ts
// The flat accessibility tree: one entry per node with semantics, in scene
// pre-order.
const dump = renderer.semantics();
for (const entry of dump) {
  console.log(entry.role, entry.label, entry.state, entry.enabled, entry.selected);
}
```

### Query / mirror the enable flag

```ts
renderer.setSemanticsEnabled(false); // JS mirror only — native store unchanged
```

### Node-level semantics (advanced)

`Node.setSemantics(descriptor)` records a `SemanticsDescriptor`
(`{ role, label?, state, enabled, selected }`) on a node; on a detached node
it is recorded and flushed to the native store on attach (the same
deferred-record pattern as `appendSpan`); on an attached node it is pushed
immediately. `Node.clearSemantics()` removes the entry (a no-op for a node
without one).

```ts
node.setSemantics({
  role: "checkbox",
  label: "Dark mode",
  state: ["checked", "focused"],
  enabled: true,
  selected: false,
});
node.clearSemantics();
```

You normally never call these directly: the component factories derive and
sync semantics automatically through `syncSemantics`, which runs at factory
creation and inside every rebuild, so state flips from `checkboxKey` /
`toggleKey` / `radioKey` / `selectKey` / `menuKey` (and the menu open/close
path) are reflected in the store.

### Per-component derivation

| Component | `role` | `label` | `state` | `enabled` / `selected` |
|-----------|--------|---------|---------|------------------------|
| Checkbox | `checkbox` | `label` prop | `checked`, `focused` | `!disabled` / `false` |
| Toggle | `switch` | `label` prop | `checked` (on), `focused` | `!disabled` / `false` |
| Radio root | `radiogroup` | — | `focused` | `!disabled` / group has a selection |
| Radio row | `radio` | option label | `checked` (selected), `focused` | `true` / row selected |
| Select | `listbox` | — | `expanded`, `focused` | `!disabled` / value confirmed |
| Input / Textarea | `textbox` | `label` prop (input) | `focused` | `!disabled` / `false` |
| Menu | `menu` | — | `expanded` | `true` / `false` |

## The native dump shape

`Renderer.semantics()` returns the flat `SceneSemanticsJs[]` dump produced by
the napi binding (`TuiRenderer::semantics`): one entry per node with a
semantics record, in **scene pre-order**, `id`/`parent` mirroring the scene
tree (the root's entry has no `parent`), state flags **sorted** for a stable
dump. Nodes whose semantics were cleared are omitted.

```ts
interface SceneSemanticsJs {
  /** The scene node id (mirrors the scene tree). */
  id: bigint;
  /** The parent scene node id; omitted for the scene root's own entry. */
  parent?: bigint;
  /** The ARIA role name. */
  role: string;
  /** The node's accessible name, or omitted when the node carries no label. */
  label?: string;
  /** The active semantics state flags, sorted for a stable dump. */
  state: string[];
  /** Whether the control is interactive. */
  enabled: boolean;
  /** Whether the node is currently selected. */
  selected: boolean;
}
```

The dump is a pure read for tests, debugging, and a11y bridges: it never
touches layout or painted content, and it is **not gated** by the store's
enable flag (entries written while enabled stay readable after disabling).
Throws on a destroyed renderer.

## Testing

`packages/core/src/semantics_test.ts` covers, per component, the derived
role / label / enabled / selected fields and the key-handler state
transitions (`checkboxKey` space → `checked`; `radioKey` down/space → the
per-row `selected` moves; `menuKey` open → `expanded`), the default-off
contract (`semantics()` stays empty even after `setSemantics` calls), and
the cell-output invariance golden (`render_to_buffer` frames byte-identical
with and without semantics set). The native store itself is covered by the
Rust tests in `src/bindings/tern-node/src/tests/semantics.rs` and
`src/core/tern-core/src/semantics.rs`.
