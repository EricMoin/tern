# Accessibility semantics (a11y)

The M4.1 semantics layer: every interactive widget exposes accessibility
metadata — an ARIA `role`, an accessible `label`, active boolean `state`
flags, and the `enabled` / `selected` booleans — through a **parallel
bookkeeping store** that never changes painted cell output. This document
covers the JS API, the native dump shape, the default-off contract, and the
M4.2 emission channels (the generic JSONL semantics stream and the opt-in
iTerm2 annotation emitter).

## Scope: the M4.1 read API plus the M4.2 emission channels

The M4.1 slice ships the semantics **tree + read API**: the metadata is
derived per component, stored in a parallel map, and readable through
`Renderer.semantics()` for tests, debugging, and third-party a11y bridges.
No ESC sequence is ever produced by the read API itself. M4.2 adds the
**emission channels** — a generic JSONL semantics stream and an opt-in
iTerm2 annotation emitter, both covered in [M4.2 a11y emission
channels](#m42-a11y-emission-channels) below. Emission is strictly opt-in
on both channels, and neither changes painted cell output.

## The default-off contract

The semantics store is **off by default**:

- A renderer constructed **without** the `semantics` option has a disabled
  native store. `Node.setSemantics` writes are **rejected** natively (and the
  JS wiring — being best-effort — catches the rejection and drops the write,
  never an error), so `Renderer.semantics()` stays empty even after
  `setSemantics` calls.
- A renderer constructed with `semantics: true` opts in: writes land in the
  store and the dump surfaces them.
- `Renderer.setSemanticsEnabled(enabled)` is the **JS-side mirror only** —
  the native store is fixed at construction (there is no native runtime
  toggle). It updates the JS bookkeeping a consumer or a11y bridge can query,
  and it stays in sync with the `semantics` constructor option. Disabling it
  never clears the store: entries written while enabled stay readable (the
  native read is not gated by the flag).

Because the store is pure bookkeeping — a parallel map of node metadata the
compositor never reads — wiring semantics never changes painted cell output.
The cell-output invariance is tested at every layer: natively (the Rust
`semantics_writes_never_change_painted_snapshot_rows` test) and from JS
(`semantics_test.ts`'s `render_to_buffer` golden).

## Roles

The ARIA role vocabulary (`SemanticsRole`):

| Role | Used by |
|------|---------|
| `checkbox` | a `Checkbox` |
| `switch` | a `Toggle` |
| `radiogroup` | a `Radio` root |
| `radio` | one option row of a `Radio` |
| `listbox` | a `Select` |
| `textbox` | an `Input` / `Textarea` |
| `menu` | a `Menu` |
| `button`, `menuitem`, `link`, `group` | reserved for future components (accepted by the native store) |

An unknown role string is rejected natively (the write errors instead of
silently dropping), so a typo surfaces rather than producing wrong metadata.

## State flags

The boolean semantics states (`SemanticsState`) a node's `state` array may
carry:

| Flag | Meaning |
|------|---------|
| `checked` | the control is in its on/selected state (a checked checkbox, an on toggle, the selected radio row) |
| `focused` | the control (or a row within it) is focused |
| `expanded` | a dropdown / menu is open |
| `collapsed` | reserved (a collapsed branch) |

State flags are sorted in the dump for a stable read. An unknown flag string
is rejected natively, like an unknown role.

## JS usage

### Opt in

```ts
import { createRenderer } from "@tern-tui/core";

// The store is off by default; `semantics: true` opts in.
const renderer = createRenderer({ headless: true, semantics: true });
```

### Read the dump

```ts
// The flat accessibility tree: one entry per node with semantics, in scene
// pre-order.
const dump = renderer.semantics();
for (const entry of dump) {
  console.log(entry.role, entry.label, entry.state, entry.enabled, entry.selected);
}
```

### Query / mirror the enable flag

```ts
renderer.setSemanticsEnabled(false); // JS mirror only — native store unchanged
```

### Node-level semantics (advanced)

`Node.setSemantics(descriptor)` records a `SemanticsDescriptor`
(`{ role, label?, state, enabled, selected }`) on a node; on a detached node
it is recorded and flushed to the native store on attach (the same
deferred-record pattern as `appendSpan`); on an attached node it is pushed
immediately. `Node.clearSemantics()` removes the entry (a no-op for a node
without one).

```ts
node.setSemantics({
  role: "checkbox",
  label: "Dark mode",
  state: ["checked", "focused"],
  enabled: true,
  selected: false,
});
node.clearSemantics();
```

You normally never call these directly: the component factories derive and
sync semantics automatically through `syncSemantics`, which runs at factory
creation and inside every rebuild, so state flips from `checkboxKey` /
`toggleKey` / `radioKey` / `selectKey` / `menuKey` (and the menu open/close
path) are reflected in the store.

### Per-component derivation

| Component | `role` | `label` | `state` | `enabled` / `selected` |
|-----------|--------|---------|---------|------------------------|
| Checkbox | `checkbox` | `label` prop | `checked`, `focused` | `!disabled` / `false` |
| Toggle | `switch` | `label` prop | `checked` (on), `focused` | `!disabled` / `false` |
| Radio root | `radiogroup` | — | `focused` | `!disabled` / group has a selection |
| Radio row | `radio` | option label | `checked` (selected), `focused` | `true` / row selected |
| Select | `listbox` | — | `expanded`, `focused` | `!disabled` / value confirmed |
| Input / Textarea | `textbox` | `label` prop (input) | `focused` | `!disabled` / `false` |
| Menu | `menu` | — | `expanded` | `true` / `false` |

## The native dump shape

`Renderer.semantics()` returns the flat `SceneSemanticsJs[]` dump produced by
the napi binding (`TuiRenderer::semantics`): one entry per node with a
semantics record, in **scene pre-order**, `id`/`parent` mirroring the scene
tree (the root's entry has no `parent`), state flags **sorted** for a stable
dump. Nodes whose semantics were cleared are omitted.

```ts
interface SceneSemanticsJs {
  /** The scene node id (mirrors the scene tree). */
  id: bigint;
  /** The parent scene node id; omitted for the scene root's own entry. */
  parent?: bigint;
  /** The ARIA role name. */
  role: string;
  /** The node's accessible name, or omitted when the node carries no label. */
  label?: string;
  /** The active semantics state flags, sorted for a stable dump. */
  state: string[];
  /** Whether the control is interactive. */
  enabled: boolean;
  /** Whether the node is currently selected. */
  selected: boolean;
}
```

The dump is a pure read for tests, debugging, and a11y bridges: it never
touches layout or painted content, and it is **not gated** by the store's
enable flag (entries written while enabled stay readable after disabling).
Throws on a destroyed renderer.

## M4.2 a11y emission channels

M4.2 turns the semantics tree into something a consumer can read *live*:
a generic JSONL semantics stream (the primary channel, works in any
terminal) plus an opt-in iTerm2 annotation emitter (VoiceOver-visible,
iTerm2 only). The two channels are independent; neither changes painted
cell output.

### The generic JSONL semantics stream

`Renderer.startA11yStream(onLine)` opens a versioned JSONL stream over the
semantics dump; `Renderer.stopA11yStream()` closes it. The stream is the
**primary** M4.2 delivery: it requires no vendor escape protocol, so a
screen-reader adapter or test harness can consume it from any terminal —
or from a headless renderer.

**Format — one line per emission, each line a complete payload:**

- A **header line** `{"v":1}` is emitted synchronously when the stream
  starts: the protocol **version marker** (`A11Y_STREAM_VERSION`, currently
  `1`; bump it on any breaking change to the emitted line shape).
- Then **one line per coalesced painted frame**: the full
  `Renderer.semantics()` dump serialized as ONE JSON array. Each array
  element is a complete pre-order semantics-tree entry — `id`, `parent`,
  `role`, `label?`, `state`, `enabled`, `selected`, the `SceneSemanticsJs`
  shape from the previous section. Scene node ids are `bigint`, which
  `JSON.stringify` throws on, so they serialize as **decimal strings**
  (`"id":"3"`, `"parent":"2"`).
- **No-change suppression**: an emission whose serialized dump is
  byte-identical to the last emission is skipped (the header is emitted
  exactly once and is never subject to suppression).

Because every line is a full serialization of the tree, the
**consumer/bridge contract** is trivial: a screen-reader adapter or test
harness parses each line independently as a complete pre-order semantics
tree — no line is a delta, and no consumer state is needed between lines.

```ts
const renderer = createRenderer({ headless: true, semantics: true });
const lines: string[] = [];
renderer.startA11yStream((line) => lines.push(line));
// ... paint frames ...
renderer.stopA11yStream(); // future emissions are dropped
```

Stream semantics (all mirrored from the M4.1 read API):

- **Pure read** — the stream never touches layout or painted content;
  painted frames are byte-identical with the stream running (proven by the
  paint-invariance unit test).
- **Best-effort** — a destroyed-renderer read error or a throwing sink is
  caught and swallowed, never propagating into the frame path; a broken
  stream must not take down a painted frame.
- **Idempotent** — `startA11yStream` while a stream is active is a no-op;
  `stopA11yStream` with none is a no-op. A destroyed renderer closes its
  stream.
- **One line per painted frame** — emission hooks into the coalesced frame
  path only (an explicit `render()` supersedes a pending frame, so the two
  paths never both fire).

### The iTerm2 reality check

The roadmap's "iTerm2 a11y report sequences" needs a reality check.
iTerm2's documented escape codes
(<https://iterm2.com/documentation-escape-codes.html>) define **no
app-facing a11y report-tree OSC protocol**: the proprietary OSC 1337 suite
covers marks, colors, notifications, clipboard writes, and free-form
**annotations** attached to a line/cell region — but no structured
semantics-tree reporting protocol an app could emit for a screen reader to
walk. The roadmap item is therefore delivered as two concrete pieces:

1. **The generic JSONL stream above** (primary) — terminal-emulator
   independent by design, testable in any terminal and from headless
   renderers.
2. **An opt-in OSC 1337 `AddHiddenAnnotation` emitter** (iTerm2 only) —
   the one escape iTerm2 does document that carries text a VoiceOver user
   can reach: `OSC 1337 ; AddHiddenAnnotation=<message> ST` attaches a
   hidden annotation to the current line/cell region without opening the
   annotation window at the time the sequence is received. The emitter
   writes each semantics entry's `role` / `label` / `state` into the
   annotation message. It is **gated on probe identity** (the terminal
   probe's `terminalIdentity` must report iTerm2), **default off**, and
   **unit-tested only** — no CI job runs a real terminal against it.

Emission stays strictly opt-in: with both channels off, the renderer emits
no a11y ESC sequence at all.

### Manual verification checklist (roadmap line 266)

Roadmap acceptance — "a11y output readable on a supporting terminal" —
checked by hand on macOS with iTerm2:

- [ ] **Enable semantics + stream.** Construct the demo renderer with
      `semantics: true`, start the JSONL stream with
      `renderer.startA11yStream(...)`, and have the sink record lines.
- [ ] **Run a demo on iTerm2.** Launch a kitchen-sink demo inside iTerm2
      (e.g. the `kitchen-sink-react` example) and interact with the
      widgets (toggle a checkbox, focus an input, open the menu).
- [ ] **Confirm annotations/stream readable.** Verify the stream emitted
      the header `{"v":1}` plus one full-dump JSON array line per changed
      painted frame (no new line while the scene is unchanged); with the
      iTerm2 emitter enabled, start VoiceOver, move focus across the
      widgets, and confirm the hidden annotations are read — and that no
      annotation window pops open (the hidden form does not reveal it).
- [ ] **Confirm default-off leaves the terminal byte-clean.** With the
      stream and emitter both off, capture the demo's raw output and
      confirm it contains no `ESC ] 1337` annotation sequence.

## Testing

`packages/core/src/semantics_test.ts` covers, per component, the derived
role / label / enabled / selected fields and the key-handler state
transitions (`checkboxKey` space → `checked`; `radioKey` down/space → the
per-row `selected` moves; `menuKey` open → `expanded`), the default-off
contract (`semantics()` stays empty even after `setSemantics` calls), and
the cell-output invariance golden (`render_to_buffer` frames byte-identical
with and without semantics set). The M4.2 stream is covered by
`packages/core/src/a11y_test.ts`: the deterministic JSONL golden (header
plus the exact full-dump line, bigint ids as decimal strings, embedded
newlines escaped), the no-change suppression contract, the paint-invariance
property (frames byte-identical with the stream running), and the
best-effort sink-error tolerance (a throwing sink never breaks the frame
path, and `stopA11yStream` cuts future emissions). The native store itself
is covered by the Rust tests in
`src/bindings/tern-node/src/tests/semantics.rs` and
`src/core/tern-core/src/semantics.rs`.
